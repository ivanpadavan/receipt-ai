### Как делаем тесты (правила)
1. Формат каждого теста: `AAA` (Arrange -> Act -> Assert).
2. В `Arrange`:
   - создаём `userEvent.setup()`;
   - рендерим через общий `render`-хелпер;
   - подготавливаем фикстуры (receipt/participants) из отдельного файла.
3. В `Act`:
   - только действия пользователя (клики, ввод, клавиатура, открытие меню/диалогов);
   - без ассертов и без побочных проверок.
4. В `Assert`:
   - сначала смысловые проверки UI/состояния (`getByRole`, `getByText`, `queryBy...`);
   - затем screenshot-проверка (`expectCurrentScreenshot`) для визуального baseline.
5. Структура тестового кода:
   - большие фикстуры выносим в `*.fixtures.ts`;
   - повторяющиеся операции/поиск элементов выносим в `helpers`/утилиты;
   - в основном тесте оставляем только сценарии и assertions.
6. Моки:
   - мокируем только внешние зависимости (router, query state, api-client, auth, provider-обвязку);
   - бизнес-логику компонента не подменяем.
7. Правила screenshot-тестов:
   - единый viewport для браузерного набора;
   - осмысленные имена baseline-файлов (по состоянию экрана/сценария);
   - обновление baseline только осознанно (`-u`) после проверки диффов.
8. Детеминизм:
   - фиксированные тестовые данные;
   - запрет на рандом/время без стабилизации;
   - после каждого теста очищаем окружение (`cleanup`, reset env/mocks).
9. Именование тестов:
   - поведенческие названия в настоящем времени (`opens ...`, `keeps ...`, `transitions ...`);
   - один тест = один пользовательский сценарий.
10. Приоритет ассертов:
   - сначала продуктовые инварианты (что пользователь видит/может сделать),
   - затем детали реализации.
